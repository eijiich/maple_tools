Star force settings

Enhancement mode (15★–21★)

A boomed Destiny is assumed to come back at 22★, the state liberation grants — so a boom costs the 10b and the stars above 22, never the 22 itself. That assumption is doing real work: recovering to the ordinary star instead would mean re-climbing 19★→22★ and roughly doubles every figure. It is also why a liberated Destiny prices below an ordinary lv250 weapon despite the 10b — the 22★ floor is worth more than the fee costs.

Milestones offered

Bundled climbs priced as one commitment. They are not the sum of the single steps — committing to the whole climb can change which mode is optimal at each star along the way.

What to do next — cheapest meso per point of main stat

SlotAxisMove Est. cost Δ stat Meso / stat Detail

Percentile blank shows the expected cost. Set 85 and the cost column becomes what it takes to actually get there 85% of the time — usually far above the average, since both systems are long-tailed. Cubing's percentile is exact (cube count is geometric); star force fits a lognormal to the mean and variance, the same approximation lostara quotes its p85 from. Flame reset is exact too, for the same reason as cubing.

Flame reset rows are behind the flame resets button and are off by default: resettable bonus stats were announced in a patch note, and until that is actually live the tool should rank exactly what it ranked before. Switch it on and flames join as a third axis; switch it off and every other row is identical, byte for byte. The button in the compare tab is the same switch. The axis exists because a flat 3m meso reset finally gives a flame a meso price to divide by. A row is “reset until it beats what the item already has, then keep it” — the patch lets you decline the new roll, so a bad reset costs only the mesos. Est. cost is the mesos that plan consumes and Δ stat the gain you end up with, but note the ratio between them is just 3m ÷ E[gain per reset]: how many resets it takes scales both and cancels, so Meso / stat depends only on how much one reset adds on average. Rates are the Black Rebirth Flame table the patch specifies, regardless of what the flames panel below is set to — that picker is for flames you own. Flame advantage still comes from each slot, and switching it off is usually why a slot looks hopeless here: it costs you two tiers on every line and drops the guaranteed 4 lines to 1–4. A slot already holding the best roll its pool can produce gets no row at all.

Enter the flame the item already has straight off the equip window; Now is what it adds up to on the same scale as everything else — which for a Final Damage paste is %fd. Flame score is the same flame in main-stat points, the number people actually quote, so a paste in %fd still reads as “130” rather than “1.32”; in a stat paste the two columns agree. Leave the fields 0 on an unflamed item. The stat columns follow your MapleScouter paste: a mage sees INT and LUK, a Xenon STR/DEX/LUK, a Demon Avenger gets an HP column — each valued at that stat's own weight, so multi-stat flames are entered exactly, not mushed through a single “secondary” number. The weights panel's “Read from the paste” line states which profile was detected. Sorted by P(better) — the chance one reroll beats what's already there, so the top row is where a flame is least likely to be wasted. Click Slot to drop back into gear order, which is easier for filling the inputs in, or any numeric heading to sort by that. Rows never move while you type — the derived columns update live and re-sorting waits for recalculate or a header click. Recalculate also re-ranks, so it takes you out of slot order back to whichever column you last sorted on. Unticking On here sinks a slot to the bottom at the next reorder and dims it straight away. It is separate from the gear table's On, so a slot can stay in the meso ranking while leaving this one. The table loads in slot order, matching the gear table; recalculate ranks it. E[gain] per roll is E[max(0, new − now)], which weighs how much better rather than how often. Rolls to beat follows this panel's own percentile box, separate from the ranking's: blank is the average roll, 85 is how many rolls make you 85% sure of beating what you have. Adv off shifts every tier down by two and drops you from a guaranteed 4 lines to 1–4, which is why it roughly quarters the expected score.

Where every number comes from

Star force cost — engine vendored verbatim from lostara_sf_caculator.html (lines 545–1035). Per-star cost divisors, the mode 1–4 rate tables, recoveryStar, star catch and the 30% boom reduction are all its numbers, not mine. Ranking uses solveUnconstrained: expected meso allowing as many booms as it takes. That is always finite. The Safe column instead uses solveSpares with one item, which is legitimately infinite above 21★ because no zero-destroy mode exists up there.

Star force stat gain — generated by tools/extract_sf_stats.py from the saved wiki page into sf-stats.js. Star caps come from where the wiki's cells go blank rather than from an assumption: lv138+ armor reaches 30★, weapons 25★, and lv128–137 stops at 20★. Note armor gains attack from 16★ up, and past 23★ the gain is only attack — no class stat at all. Class Stat +N means +N to every class-relevant stat, so it is multiplied by the sum of your flat stat weights.

Cubing — cubing.js ports calc_prob from backend/maple_cubing/cubing.py and matches it on 330 of 330 (pool, cube, target) combinations. One deliberate divergence: cubing.py's hat_unique_prob has Zero at 41/52, which makes that pool sum to 1.077 instead of 1 — the only one of 22 pools that doesn't. It should be 37/52 (5+4+6+37 = 52, matching bottom and shoes). Left uncorrected it made hat targets read about 6% cheaper than they are. Worth fixing in cubing.py too.

Item level 151+ raises potential line values by exactly one point in GMS, per StrategyWiki's Potential System page (saved under reference/): a legendary main-stat line is 12% below the threshold and 13% at or above, unique goes 9%→10%, and ATT% and All Stat% follow the same rule. Lines whose value sits in the line name do not scale — Ignore DEF 30/35/40, Boss Damage 30/35/40, the cooldown lines, and MaxHP% at unique and legendary. This is the 160+ rule in practice — no equipment exists between 151 and 159, so of the real item levels it applies to 160, 200 and 250. The wiki words it as 151+, which is why the constant reads that way. cubing.py has no item-level concept and always uses the lower values, so passing level 0 reproduces it exactly — which is how parity is still checked.

Cooldown is a constraint, not a score. There is no seconds-to-main-stat exchange rate, so a cooldown line can't be valued. Instead, asking for −2s on a hat filters the roll space to outcomes that deliver it, which pins one of the three lines and removes three-stat-line results entirely — the reachable stat ceiling drops from three 12% lines to two. Every probability then becomes a joint one, so the price of “cooldown and this much stat” is correct and can be compared against the unconstrained rows by eye. That comparison is yours to make; the tool won't pretend to convert seconds into stat.

Main-stat% and all-stat% count as one currency. All-stat does also lift your secondary stat, so it is strictly worth a shade more per point — 13.84 against 12.21 on the sample weights. Scoring that gap made the scan treat 13+10+7 and 10+10+10 as different goals despite both being 30% stat, so the ladder filled with lateral rerolls: three rows at 383, 394 and 399 all captioned “stat 30”. It was also ranking 27% all-stat above 30% main-stat, recommending a downgrade. Both are now scored at the main-stat weight, so any composition summing to the same percentage is the same target, and an item already at 30% is offered 33% and up rather than another 30%. Flames keep the distinct all-stat weight, since no main-stat% flame line exists to conflate it with. The collapse is also conditional on the weights being close (within 1.6×), which is every single-stat class — see the classes paragraph below.

Classes come from the weights, not a picker. MathBro's flame calculator needs a class dropdown (10 / 8 / 8 junk slots for a standard class / Xenon / DB-Shadower-Cadena) because it asks for hand-typed equivalences; here the same splits fall out of the MapleScouter paste by construction — every stat and combo flame slot is valued per-stat, so a Shadower's DEX and STR or Xenon's double-counted pairs just work. Two pieces are explicit: flat-HP flame lines are valued by the paste's HP weight and the HP column appears only when that weight is nonzero (Demon Avenger, whose flame score is HP); and for Xenon, All Stat% keeps its true weight (roughly triple a single stat%) while DEX%/STR%-style potential lines are lifted out of the junk pool once they are worth at least a quarter of the main stat's % weight. Kanna was reworked into a standard mage and needs nothing special. One known DA gap: star force below 16★ grants flat HP that the stat tables drop as combat-irrelevant, so DA star force is slightly undervalued.

Revealing the potential is charged on top of the cube, once per use: 20 × level² above level 120, so 450k on a lv150 item and 1.25m on a lv250 one. From cubes_CDdL.js in MathBro's cubing calculator (getRevealCostConstant / cubingCost); cubing.py omits it, so cube costs here used to read low. It adds about 2% at lv150 and 6% at lv250, and because it's a flat fee per cube it weighs proportionally heavier on the 12m red than the 22m black — up to 10% on a red-cube target at lv250. Enough to shift the odd rung, not enough to overturn red's lead.

Both cube types compete rather than being a setting. Line 1 is always a prime roll for either cube, so any target reachable through that one line has identical odds with black or red — and red costs 12m against black's 22m, so red simply wins. Black only overtakes when the target needs two or three prime lines, where its 0.2 / 0.05 prime odds beat red's 0.1 / 0.01. Each rung of the ladder is labelled with the cube that achieves it, and the frontier is recomputed after merging the two — two individually-Pareto ladders contain entries that dominate each other once combined.

Cube targets are not typed in. Every reachable 3-line combo is valued, then for each distinct total V, “reroll until worth at least V” is priced at cubeCost / P(≥V) with gain E[value | ≥V] − current. The list is then reduced to its Pareto frontier, so each entry buys strictly more stat than the one above it at a worse rate. Read it as a ladder and pick your rung — the top entry is often a trivially small win.

Secondary weapons have no stat table yet. The wiki page has only a Weapons and an Armor & Accessories section and never says which one applies — almost certainly because Astra secondaries are new enough that it hasn't caught up. Since secondaries normally aren't star forced at all (they're a cubing slot), the row ships with SF off and its Tbl set to the hand-maintained placeholder in sf-stats-secondary.js. Fill that file in and flip SF on; until then, switching SF on just reports the missing table rather than pretending the slot is maxed. sf-stats.js is generated and would be overwritten, which is why the placeholder is a separate file.

Known softness. IED is valued linearly in the line's stated percentage, but really stacks as 1−(1−a)(1−b), so an item carrying two IED lines is somewhat overvalued. Flames appear only when flame resets is switched on, since that axis is priced off the meso bonus-stat reset; with it off there is no meso figure for a flame and it stays out of a meso-per-stat ranking, exactly as before.

Meso / stat is each character's own main stat point — MapleScouter normalises every paste to 1 — so this ranks who buys a stat point cheapest. That is the right question when a stat point is worth about the same to each of them, which holds for characters at similar progression; it drifts if their totals differ a lot, because then one point is a different share of their damage. Rolls to beat carries no such caveat: it comes from a probability, and probability doesn't care how a character's weights are scaled — so it compares across characters exactly. Sorted fewest-rolls-first, so the top rows are where flames go furthest; it follows the flame panel's percentile box. Unticking a character filters instantly; ticking one recomputes. Comparing runs every selected character from scratch, so it never happens on its own — edit anything and this table will say it needs recalculating rather than show stale figures.
